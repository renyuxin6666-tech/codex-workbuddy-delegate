# Follow-up repair after the 2026-09-23 preflight

**Scope:** compatibility MCP config/state routing and safe WorkBuddy JSON
handling. This is an implementation verification, **not** a scored A/B result.
The paired experiment remains at **0/12 pairs**.

## Changes in plugin 0.1.1

- The compatibility `.mcp.json` passes the plugin-data and explicit path
  variable names to its launcher. The launcher uses a *paired* explicit config
  and state path when provided, otherwise plugin data. It refuses to start if
  neither is available or if only one explicit path is supplied. It no longer
  silently selects `%LOCALAPPDATA%/WorkBuddyDelegate` for a plugin session.
- The bridge accepts complete JSON or JSONL WorkBuddy event output. It still
  rejects mixed JSON/log text, missing success events, worker tool calls, and
  invalid citations. Malformed output returns only shape and size metadata;
  recognizable permission/network/login diagnostics are categorized without
  returning raw CLI output.
- The single-file smoke helper can exercise either the direct Python server or
  the compatibility launcher with explicit paths.

## Verification and limits

- `python -m pytest -q`: **41 passed**. This includes launcher path parity,
  fail-closed startup, JSONL parsing, and non-leaking error tests.
- The installed plugin version is `0.1.1+codex.2026092315`; the installed
  launcher, bridge, and MCP manifest matched tested source file hashes.
- The installed compatibility launcher completed an actual dry-run against the
  same config/state paths reported by the native desktop plugin, with the
  expected WorkBuddy model, allowed file, and `request_sent=false`.
- One post-repair **live** public-fixture call returned a sanitized
  `login_required` worker diagnosis. This classification is heuristic, based
  on CLI diagnostics. The call did not produce a worker answer or attributable
  WorkBuddy usage; whether a provider request or charge occurred is unknown.
  It was not retried. WorkBuddy's application process and local config directory
  existed; neither fact proves that the headless CLI was signed in.

**Result:** the configuration split is fixed in the tested compatibility
launcher, and the JSON parser/error boundary has regression coverage. A
successful live WorkBuddy result after this repair is **not yet verified**.
